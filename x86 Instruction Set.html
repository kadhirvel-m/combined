Technical Breakdown: Under the Hood

Core Concepts

  • CISC Architecture: Complex Instruction Set Computer, one instruction can do a lot.
  • Registers: Small, high-speed storage locations within the CPU.
  • Memory Addressing: How CPU finds data in RAM (e.g., base-index-scale).
  • Operands: Data or memory locations instructions operate on.

Key Registers

  • EAX/RAX: Accumulator, return value.
  • EBX/RBX: Base register.
  • ECX/RCX: Counter register.
  • EDX/RDX: Data register.
  • ESP/RSP: Stack Pointer.
  • EBP/RBP: Base Pointer (frame pointer).
  • EIP/RIP: Instruction Pointer (next instruction address).
  • EFLAGS/RFLAGS: Status and control flags.

Instruction Categories

  • Data Transfer: MOV, PUSH, POP
  • Arithmetic: ADD, SUB, MUL, DIV
  • Logical: AND, OR, XOR, NOT
  • Control Flow: JMP, CALL, RET
  • String Operations: MOVSB, CMPSB

Simple Assembly 


section .data
    msg db "Hello, World!", 0xA

section .text
    global _start

_start:
    ; Write "Hello, World!" to stdout
    mov rax, 1             ; syscall number for sys_write
    mov rdi, 1             ; file descriptor 1 (stdout)
    mov rsi, msg           ; address of message to write
    mov rdx, 14            ; message length
    syscall                ; invoke kernel

    ; Exit program
    mov rax, 60            ; syscall number for sys_exit
    mov rdi, 0             ; exit code 0
    syscall                ; invoke kernel

This snippet writes "Hello, World!" to the console using Linux x86-64 system calls.

Pipelining & Performance

Pipelining is a technique where multiple instructions are overlapped in execution. Instead of waiting for one instruction to fully complete all its stages (Fetch, Decode, Execute, Writeback) before starting the next, a pipelined CPU can have several instructions in different stages simultaneously.

Without Pipelining (Sequential)


Inst 1: F D E W
Inst 2:       F D E W
Inst 3:             F D E W

With Pipelining (Overlapped)


Inst 1: F D E W
Inst 2:   F D E W
Inst 3:     F D E W

Pipelining significantly boosts throughput by keeping CPU resources busy, but introduces challenges like "pipeline hazards" (e.g., data dependencies).
