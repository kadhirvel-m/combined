# Momentum Based GD

## Introduction
Momentum-based Gradient Descent is an optimization algorithm used to train machine learning models, serving as a variant of the traditional gradient descent algorithm [Scaler]. It enhances the efficiency of gradient descent by incorporating a "momentum" term into its weight update rule, helping to accelerate convergence and navigate challenging loss landscapes more effectively [GFG, Scaler].

## TL;DR
*   **Momentum-based Gradient Descent** is an optimization algorithm used to train machine learning models [Scaler].
*   It's a **variant of traditional Gradient Descent** that adds a **momentum term** to the weight update rule [Scaler].
*   **Momentum** is inspired by physics, where motion depends on previous velocity and current force [GFG].
*   It helps **accelerate convergence**, **escape local minima**, and **dampen oscillations** in the loss function [Scaler].
*   Key **hyperparameters** include **learning rate (η)** and the **momentum factor (ρ or β)** [GFG, Scaler].
*   Updates involve calculating **velocity (v)** based on previous velocity and current gradient, then updating weights using this velocity [GFG].
*   **Nesterov Accelerated Gradient (NAG)** and **AdaMomentum** are advanced variants [GFG].

## Understanding Gradient Descent
**Gradient Descent** is a fundamental optimization algorithm used to minimize a **loss function** (or cost function) by iteratively moving in the direction of the steepest descent, defined by the negative of the gradient [GFG, Scaler].

### How Gradient Descent Works
The algorithm iteratively adjusts a model's **weights (parameters)** by taking small steps proportional to the negative of the gradient of the loss function with respect to the weights [GFG, GFG].
*   It minimizes a **cost function**, which quantifies the error between the model's predictions and true labels [GFG].
*   The gradient indicates the direction of the steepest increase in the loss function; moving in the negative direction minimizes it [Scaler].
*   **Loss function (J)** for a single row can be simplified to $J(w, b) = \frac{1}{n} (y_p-y)^2$ for illustrative purposes [GFG].

### Applications of Gradient Descent
Gradient Descent (or its variants) is used to train machine learning models across various domains:
*   **Neural Networks:** Trained using Gradient Descent in combination with **backpropagation**, which computes gradients of the loss function with respect to each parameter [GFG].
*   **Linear Regression:** Minimizes **Mean Squared Error (MSE)** to find the best-fit line by iteratively updating weights (coefficients) and bias [GFG].
*   **Logistic Regression:** Minimizes **Log Loss (Cross-Entropy Loss)** to optimize the decision boundary for binary classification [GFG].
*   **Support Vector Machines (SVMs):** Optimizes the **hinge loss** to ensure a maximum-margin hyperplane [GFG].

### Problems with Traditional Gradient Descent
Traditional Gradient Descent can face several challenges [Scaler]:
*   **Local Minima:** The algorithm can get stuck in **local minima**, which are not the global minimum of the cost function, preventing optimal model training [Scaler].
*   **Slow Convergence:** In regions with shallow gradients or when the loss landscape is flat, convergence can be very slow [Scaler].
*   **Oscillations:** When the loss surface is highly anisotropic (different curvatures in different directions), GD can oscillate back and forth across narrow valleys, slowing down progress towards the minimum [Scaler].

### Gradient Descent Variants
To address some limitations, different variants of Gradient Descent exist:
*   **Batch Gradient Descent (BGD):**
    *   Uses the **entire dataset** to compute the gradient and update parameters in each iteration [GFG].
    *   **Advantages:** Stable convergence, global view of the dataset [GFG].
    *   **Disadvantages:** Computationally and memory intensive for large datasets [GFG].
*   **Stochastic Gradient Descent (SGD):**
    *   Updates parameters using the gradient of the loss function with respect to a **single training example** at a time [GFG].
    *   **Advantages:** Faster convergence (due to frequent updates), less memory intensive [GFG].
    *   **Disadvantages:** Noisy updates leading to an erratic convergence path, potential for overshooting the minimum [GFG].

## Momentum-Based Gradient Descent: Overview
Momentum-based gradient descent is a variant that adds a **momentum term** to the update rule, addressing some of the problems of traditional gradient descent [Scaler].

### What is Momentum?
From physics, **momentum** describes an object's motion depending on both the current force and its previous velocity [GFG]. In optimization, this concept is applied to weight updates. It means that the optimization algorithm not only considers the current gradient but also retains a "memory" of past updates, allowing it to move more consistently in the correct direction [GFG, Scaler].

### How Momentum Helps Fix Problems
By incorporating previous updates, momentum-based GD can:
*   **Accelerate Convergence:** When gradients point in the same direction over consecutive iterations, the momentum term accumulates, leading to faster movement towards the minimum [Scaler].
*   **Escape Local Minima:** The accumulated momentum can provide enough "inertia" to push the optimizer past shallow local minima or saddle points, helping it reach deeper minima [Scaler].
*   **Dampen Oscillations:** In areas where gradients change direction frequently (e.g., narrow valleys), momentum helps smooth out the updates, reducing oscillations and allowing for more direct progress [Scaler].

## How Momentum-Based Gradient Descent Works
Momentum-based gradient descent works by adding a fraction of the **previous weight update** to the **current weight update** [Scaler]. The core idea is to maintain a "velocity" in parameter space that influences future updates.

The update rule involves two main steps:

1.  **Velocity Update:** The **velocity (v_t)** at iteration `t` is updated by considering both the **previous velocity (v_{t-1})** and the **current gradient** [GFG].
    $v_t = \rho \cdot v_{t-1} + \eta \cdot \nabla J(w_t)$
    Where:
    *   $v_t$ is the new velocity vector.
    *   $v_{t-1}$ is the previous velocity vector.
    *   $\rho$ (rho) is the **momentum hyperparameter** or **momentum factor**, controlling the contribution of the previous velocity (typically set to 0.9) [GFG, Scaler].
    *   $\eta$ (eta) is the **learning rate** [GFG, Scaler].
    *   $\nabla J(w_t)$ is the gradient of the loss function with respect to the weights $w_t$ at the current iteration [GFG, Scaler].

2.  **Weight Update:** The model's **weights (w_t)** are then updated using the calculated velocity [Scaler].
    $w_{t+1} = w_t - v_t$
    Where:
    *   $w_{t+1}$ is the updated weight vector.
    *   $w_t$ is the current weight vector.
    *   $v_t$ is the velocity vector calculated in the previous step.

## Hyperparameters
Two crucial hyperparameters control the behavior of momentum-based optimizers:

*   **Learning Rate (η):**
    *   Determines the **size of the step** taken during each weight update [GFG].
    *   A high learning rate can cause overshooting, while a very low one can lead to slow convergence [GFG].
*   **Momentum Factor (ρ or β):**
    *   Controls the **contribution of the previous velocity** to the current velocity update [GFG].
    *   A higher momentum factor (e.g., 0.9) means previous updates have a stronger influence, leading to smoother and faster movement in consistent directions [GFG, Scaler].
    *   If **ρ** is too high, the optimizer might overshoot the minimum; if too low, it might not fully leverage the benefits of momentum [needs review]. The typical value is 0.9 [Scaler].

## Types of Momentum-Based Optimizers
Several variations exist, each with modifications to the basic momentum algorithm:

1.  **Nesterov Accelerated Gradient (NAG):**
    *   An advanced form of momentum-based optimization [GFG].
    *   It modifies the update rule by calculating the gradient at an **"upcoming" position** (a lookahead step) rather than at the current position of the weights [GFG]. This allows it to correct its trajectory faster.

2.  **AdaMomentum:**
    *   Combines the concept of **adaptive learning rates** with momentum [GFG].
    *   It adjusts the momentum term based on the recent gradients, making the optimizer more sensitive to the landscape of the loss function [GFG].

3.  **RMSProp (Root Mean Square Propagation):**
    *   While not strictly a momentum-based optimizer in the traditional sense, RMSProp incorporates a form of momentum by **adapting the learning rate for each parameter** [GFG].
    *   It's particularly effective when dealing with non-stationary objectives and helps mitigate vanishing/exploding gradients [GFG].

## Examples
Consider the problem of training a neural network for image classification.
*   Without momentum, the optimizer might struggle in flat regions of the loss landscape or oscillate when navigating narrow valleys, leading to slow training [Scaler].
*   With momentum, the network's weights update with a "memory" of past updates. If the loss consistently decreases in a certain direction, momentum builds up, allowing the optimizer to move faster through that region. If it encounters a small bump (local minimum), the accumulated momentum can help it push past, leading to a potentially better solution and faster training convergence [Scaler].
*   In **Linear Regression**, momentum helps quickly find the optimal coefficients by smoothing the descent path, especially with noisy data or large datasets, preventing getting stuck in suboptimal local minima (though MSE for linear regression is convex and has only one global minimum, momentum still speeds up convergence) [GFG, Scaler].

## Memory Aids
*   **"Ball Rolling Down a Hill":** Imagine a ball rolling down a hill (the loss landscape).
    *   **Gradient Descent** is like giving the ball a push based on the current slope [GFG].
    *   **Momentum-based GD** is like the ball gaining speed as it rolls, so it doesn't stop immediately if it hits a small dip (local minimum) and can roll past flat areas faster [Scaler]. The "momentum factor" controls how slippery the hill is (how much speed it retains).
*   **"Consistent Direction":** When the gradient consistently points in one direction, momentum amplifies the step, like a snowball rolling downhill gathering more snow and speeding up.

## Common Mistakes
*   **Incorrect Learning Rate (η):** Setting the learning rate too high can cause divergence or overshooting the minimum. Too low can lead to extremely slow convergence [GFG].
*   **Incorrect Momentum Factor (ρ):** A momentum factor that is too high can cause the optimizer to overshoot the minimum or oscillate uncontrollably. A very low momentum factor might negate the benefits of using momentum [needs review].
*   **Not Understanding Base Gradient Descent:** Attempting to use momentum-based optimizers without a solid grasp of how traditional Gradient Descent works can lead to misinterpretation of results and difficulty in debugging [GFG].
*   **Ignoring Hyperparameter Tuning:** Assuming default values for $\eta$ and $\rho$ will always work optimally. These hyperparameters often require careful tuning for specific datasets and models.

## Conclusion
Momentum-based Gradient Descent is a powerful optimization algorithm that significantly improves upon traditional gradient descent by incorporating a momentum term. This allows models to learn faster, navigate complex loss landscapes more efficiently, and achieve better performance by overcoming challenges like local minima and oscillations. Understanding its mechanics and hyperparameters is crucial for effective machine learning model training.
